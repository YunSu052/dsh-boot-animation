# boot-splash

自建 DSH **启动画面**插件：开机时叠一段全窗口画面（默认为渐变底），片尾交叉溶解进界面。

**为什么自己写**：那款第三方插件（`dsh-boot-animation`）的功能能用，但它的设置卡片在桌面端**永远出不来**，因为它把配置卡挂到了 `plugins.item` —— 那是**官方插件**用的槽位；asar 里 harness 自带的作者文档写明，第三方 **bundle** 的配置应挂 `plugins.bundle.config`（以包名为键）。另外它还有一串会咬人的坑（`tools/` 不在 npm `files` 白名单、`install.ps1` 用本机端口判成败会误回滚、成功日志藏在 `?dshbootdiag=1` 后面、静态 import 缺 peer 即整插件死、卡片从没在真机 GUI 验证过）。本插件把这几点逐个改掉。

## 三个文件

| 文件 | 跑在哪 | 干什么 |
|---|---|---|
| `host.js` | DSH 进程 | 读配置、挂 4 条路由（清单/体检/配置读/配置写/素材字节）、订阅 `webserver/index-inject` 注入开机面板 |
| `panel.js` | 浏览器（**外壳模块之前**） | 开机覆盖层本体：框架无关、注入为 head 脚本；每条走不下去的路都有上界，且**失败必定可见** |
| `client.js` | 浏览器（客户端插件） | ①向面板报到（`clientReady`）②把设置界面**两条通路都挂** |

## 两条 DSH 事实（写死在代码里的前提，别动）

1. **`webserver/index-inject` 是唯一足够早的时机** —— 推进去的行会渲染进 `<head>`，早于外壳模块；更晚的任何手段都盖不住内核启动页。
2. **路由必须 `exact`，只有 `/clip` 用 `prefix`** —— 在 `/plugins/boot-splash` 上挂 prefix 会把 `/plugins/boot-splash/client.js` 一起吃掉，而那是 client-modules 用来物化本包客户端 bundle 的 URL ⇒ 客户端半侧永远加载不了。

## 配置

文件：`$DSH_HOME/boot-splash.json`（默认 `~/.dsh/boot-splash.json`）。**不存在也能跑**（用默认值）。

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉 = 一行都不注入、一次素材请求都不发（真关，不是"脚本自己判断"） |
| `fadeMs` | `2000` | 淡入淡出时长，0–10000 |
| `enterMode` | `"tail"` | `tail` 片尾交叉溶解 / `end` 放完再淡 / `click` 点击才进 |
| `holdMs` | `15000` | 最长等待：内核迟迟不就绪时，到点提示"点一下可以进入" |
| `dir` | `""` | 素材目录（绝对路径或 `~/`）。**留空 = 用包内自带素材**（`assets/videos`）；两边都没有则只有渐变底。**想只要渐变底**就把 `dir` 指向一个空目录 |
| `clips` | `[]` | 参与轮播的文件名；空 = 目录里所有 `.mp4/.webm/.m4v/.mov` |
| `sound` | `"gesture"` | 声音：`gesture` 静音起播、第一下点击开声（默认）/ `auto` 先试带声自动播放（浏览器可能拒，会退回静音）/ `mute` 始终静音且不提示 |
| `volume` | `100` | 音量 0–100 |
| `delayMs` | `0` | **起播前先等这么久**（0–10000），期间只显示渐变底。用来躲开宿主的启动期——见下面「已知边界」里的起播卡顿 |
| `diag` | `false` | 诊断模式：面板记录播放质量并回传，宿主落盘 `$DSH_HOME/boot-splash-diag.json`。**默认关 = 一个字节都不写、一个多余请求都不发** |
| `bg` | `""` | **代码窗背景图**：图片文件的绝对路径或 `~/` 开头；留空 = 不用（保持渐变底）。只认这一个配置项 ⇒ `/bg` 路由的路径**不由请求决定**，没有穿越面 |
| `bgColor` | `""` | 覆盖层**底色**（CSS 颜色，≤64 字符）；**留空 = 不画底色**（覆盖层透明，启动瞬间直接透出宿主画面）。与 `bg` 的关系：纯色是**底色**、图片画在它上面 ⇒ 可同时配，图片读不到时看到的是你挑的颜色。**不被 `bgDim` 压暗**（那只作用于图片） |
| `bgGradient` | `true` | **内置深色渐变底**（深蓝 radial），**默认开**。作用有两个：①以前它是写死在 CSS 里的（导致 `bgColor` 留空也有颜色），现在改成 `data-bgmode` 驱动的显式模式；②**盖住 DSH 外壳自己的启动页**（那个转圈 logo + 进度弧）——覆盖层全透明就会看见它（2026-10-11 用户报"进入瞬间会出现转圈的 logo"）。想要全透明就关掉。与 `bgColor` 可叠加（纯色在下、渐变在上） |
| `bgDim` | `60` | 背景图**压暗强度** 0–100（默认 60）：不压暗的话亮图上的字会读不清。压暗层用 `::before` 只画一次、不参与动画 ⇒ 合成开销可忽略 |
| `wordmarkSize` | `0` | 词标字号（像素，0–40）：**`0` = 按列宽自动适配**（默认，防溢出） |
| `wordmarkShine` | `false` | 词标**流光光效**（**不受系统「减少动态效果」影响**：它是你显式打开的 ⇒ 显式压过隐式；系统偏好只在设置页作为提示出现）。⚠ 实现是「渐变 + `background-clip:text` + 逐帧挪 `background-position`」⇒ **每帧重绘这块文字**（面积小、非全屏，但不是纯合成）；故**默认关**，系统开「减少动态效果」时自动退回静态单色 |
| `wordmarkShineColor` | `"#8ff0ff"` | 流光颜色（CSS 颜色字符串；下发前会剥掉 `;{}`、`<>` 等字符） |
| `wordmark` | `"Exploring the unexplored"` | 日志打完后追加的**大写词标**，由代码的 5×7 方块字模绘制（不是图片）。换行或 `|` 分行；空字符串 = 关掉词标 |
| `lineGapMs` | `120` | 状态窗每行**至少**间隔多久露面（0–2000）——**回放节奏，不是实测**；行首时间戳仍是实测值。`0` = 不节流 |
| `mode` | `"video"` | 启动画面形态：`video` 全窗口视频（原行为）/ `status` **启动状态窗**（不播视频，只显示启动过程）/ `both` 视频作背景 + 状态面板叠加 |
| `coverTitlebar` | `true` | **画面铺满整窗**（连 Windows 标题栏那一条一起盖）。原理见下方「标题栏：从让出到铺满」一节 |
| `titlebarControls` | `"hover"` | 标题栏三个窗口按钮图标：`hover` 悬停才浮出（平时透明，推荐）/ `hidden` 始终透明 / `visible` 始终显示（画面顶部很亮时用） |
| `clickFullscreen` | `true` | **点一下进真全屏**（连任务栏一起盖住）。⚠ 全屏必须由**用户手势**触发（浏览器内核限制，见下方「全屏」一节），所以做不到"开机自动全屏"。⚠ 这一下点击**只进全屏（+开声音），不再顺带进入界面**——想提前进请双击 |
| `doubleClickSkip` | `true` | **双击跳过动画**：两次点击间隔 <320ms 直接进入界面，且不受"外壳是否就绪"闸门限制（单击在开机头几秒只会先开声音并提示等待） |
| `exitFullscreenOnEnter` | `true` | **进入界面时退出全屏**（推荐开）。Windows 真全屏会**收走最小化/最大化/关闭按钮**（系统行为、插件改不了），不退出的话用户就"出不去"了。**关掉它 = 双击跳过后保持全屏**，那时退出靠 Esc 或下面那个自绘按钮 |
| `fullscreenExitButton` | `true` | **自绘「退出全屏」按钮**：全屏期间在右下角常驻一个小按钮，点一下退出全屏、原生窗口按钮立刻回来。只在**真的处于全屏**时显示（非全屏一个像素都不占）。键盘 **Esc 始终可用**，不受本开关影响 |

> **写在硬编码里的教训**：`panel.js` 里有一段以「⚠ 这里故意不做」开头的注释，说明**为什么不用「等 first paint 再起播」**。那条闸门实现过、测过、又撤了（前提不成立 + 判据自身行为无法解释）。要动起播时序前先读它，别再走一遍。

> **为什么不能"自动就有声音"**：Chromium 的策略是**没有用户手势就不允许带声音自动播放**，页面里无法绕过（这是宿主窗口的 `autoplayPolicy`，插件改不了）。所以默认是"静音起播 + 第一下点击开声"，`auto` 只是"先试一次"，被拒会退回静音并在提示行写出原因。

**坏配置不会让插件挂**：字段逐个校验，不合格的落回默认值并把原因记下来（`/status.json`、宿主日志、设置界面里都能看到）。写盘是原子写（先写临时文件再改名），且**只合并**——界面上只改一项不会把别的项抹掉。

## 启动状态窗（`mode: "status"` / `"both"`）

把「开机那几秒程序到底在干什么」显示出来。**只显示实测到的**，每行都标来源：

| 来源 | 是什么 | 怎么来的 |
|---|---|---|
| `host` | 宿主进程侧事件（模块加载 / apply / 路由挂载 / 注入面板） | 宿主用**绝对时间戳**记录，随配置注入页面 |
| `panel` | 面板自身进度 | 自己 |
| `shell` | DSH 外壳启动页：**真实激活进度** + 外壳自己的提示与失败文本 | 读 `[data-dsh-boot]` 与它的 `--dsh-boot-arc` |
| `net` | 资源加载（外壳 JS、插件 combo 的体积与耗时） | `performance.getEntriesByType('resource')` |
| `renderer` | DOMContentLoaded / load / 首次绘制 / 外壳就绪 | 标准 API |

**展开动画**：状态窗出现时做一次 360ms 的展开（`transform`+`opacity`）——**只走合成器、不触发重排重绘**，且只跑一次；这是对「面板要廉价」的**有依据的放宽**（当初出问题的是每帧混合视频帧与模糊，不是一次性变换）。系统开了「减少动态效果」时自动不做。

**代码绘制的词标**：日志与回放结束后，追加 `wordmark` 指定的大写英文（默认 `Exploring the unexplored`，渲染为大写 `EXPLORING THE UNEXPLORED`，约 149 列 ⇒ 字号按列宽自适应），用代码里的 5×7 方块字模**自上而下逐行打印**，且**紧接在日志下一行**；打完停 `700ms` 再进界面。它是**文本**，合成开销为零。

**逐行回放**：真实执行可能几百毫秒内就把几十条事件全挤出来，所以每行**至少隔 `lineGapMs`（默认 120ms）**才露面；回放没追平前不自动进入（否则尾部几行会被一起带走）。⚠ 这是**回放节奏**：界面表头写着「逐行回放（行首时刻为实测）」，行首时刻仍是真实测量值，节奏是呈现。

三条写死的规矩：

1. **没读到就写「不确定」**——例如激活进度读不到进度弧时，绝不编百分比、绝不编时间。
2. **时间轴一律用绝对时刻**：面板的 `performance.now()` 与宿主进程的时钟原点实测差 **1.4–2.1 秒**，用相对时钟排序会把先后顺序显示错。
3. **失败要看得见**：外壳报出失败时该条标红，并且**不自动进入**，直到你点一下或到绝对上限。

> **两处诚实的局限**：① 读 `[data-dsh-boot]` 属于**依赖 DSH 内部实现**，升级可能失效——失效时自动降级为「激活进度：不确定（shell 未提供）」，其余来源不受影响。② 面板刻意做成**纯文本、200ms 一次、只在文本变化时写 DOM**，不做模糊/渐变/动画；启动期抢合成资源的代价我们实测过（见下面「已知边界」的起播卡顿），别把它挖回来。

## 设置界面：两条通路都挂

- `settings.section` —— 设置里的整页「启动画面」（皮肤插件用的就是它）
- `plugins.bundle.config` —— 插件页里按包名分组的配置位（keyed 槽）

> **两条通路的实测结论（2026-10-02 真机验证）**：**都必须用 `slots.inject(槽名, cb)` 等槽出现，再在回调里 `slots.register(...)`**。
> 直接 `slots.register(...)` 会抛 `slot "…" is not declared (a parent entry's children table must declare it)` —— 这些槽是由父条目（设置页 / 插件页）声明为子槽的，页面还没挂上时它们并不存在。
> keyed 槽的正确形状：`slots.register({ name: 'plugins.bundle.config', key: '<包名>' }, Component)`。
> （同一个坑：部署里的 `meow-memory` 也用直接 register，于是每次语言变化都在控制台抛同一个错。）

**读写在宿主路由上**（`GET/POST /plugins/boot-splash/config.json`），**不碰 DSH 设置服务** ⇒ 不依赖 schemastery / `.volatile()` / `whileServed` 那一整条链——那正是上一款插件"卡片静默消失且无错可查"的来源。

写接口的两道守卫：必须带 `x-boot-splash-write: 1` 头（跨源简单请求带不上自定义头），且带 `Origin` 时必须是本机回环。残余风险：**本机任意进程**仍可直连回环写这个配置（它只影响自己的启动画面，影响面有限）。

## 安装 / 更新 / 卸载

**装**（两条路，选一条）：
1. **App 插件管理器**（推荐，官方入口）：侧栏「插件」→ 添加插件 → 粘**本插件所在目录的绝对路径**（你 clone / 解压到哪就填哪，跨机器一样）；
2. **手工接线**（开发用，即时生效）：在 `<profile>/node_modules` 下建 junction 指向本目录，并把 `"boot-splash": "link:<本目录>"` 加进 profile 的 `dependencies`，同时把 `"boot-splash"` 加进 `dsh.profile.bundles`。

**生效规则**（改完要不要重启）：改 `panel.js` / 配置 / 素材 ⇒ **刷新页面**即可；改 `host.js` **或 `client.js`** ⇒ **必须重启 DSH**（`client.js` 由宿主在启动时快照进内存，刷新页面**永远**不够）。设置页底部会显示「本设置界面（客户端半侧）加载于 hh:mm:ss」——那个时间早于你最近一次重启，就说明页面跑的是旧代码。

**卸**：删 junction + 去掉那两处记账 + 删配置行（若你手工加过 `cordis.patch.yml` 的行，也一并删掉）。

### 换一台电脑装（跨机器自足）

本包**刻意做成自足**，换机器不需要任何额外准备：

- **无依赖**：`package.json` 里**没有 `dependencies`、也没有 `peerDependencies`** ⇒ 不跑 `pnpm install`、不需要 schemastery（那正是上一款插件"静态 import 解析不到就整个插件死"的来源）；
- **无本机路径**：宿主侧路径全部来自 `import.meta.url` / `process.env.DSH_HOME` / `os.homedir()`，代码与配置里**没有任何写死的盘符**；
- **自带素材**：三段 mp4 随包分发（见下方署名），所以**装完即有画面**，不用再配 `dir`；
- **平台差异有兜底**：顶部"让出系统标题栏"只在检测到 `[data-windows-titlebar]` 时生效，macOS/Linux 自动不偏移；全屏态也不偏移。默认 `coverTitlebar: true` 时改为"铺满并临时透明化覆盖层"，关掉它即回到旧的让位行为；
- **需要**：DSH 桌面端（0.2.0-rc.2 级别，客户端插件体系 + `webserver/index-inject` 钩子）；Node ≥ 22.19 仅在你跑 `tests/` 时需要。

装法同上：App 插件管理器 →「添加插件」→ 粘**这份目录**的绝对路径 → 安装 → **重启 App**（宿主半侧换了就要重启；之后改设置只需刷新）。

## 标题栏：从让出到铺满

**问题**（2026-10-02 用户报）：Windows 桌面端的窗口按钮是系统画的 `titleBarOverlay`，图标色取自宿主探测到的 chrome 调色板（浅色主题是近黑 `#0f1115`），而背景在开机早期是透明的 ⇒ 全屏覆盖会把它们衬成"黑底黑图标"。
当时的解法是**让出标题栏那一条**（高度取宿主的 `--dsh-windows-titlebar-height`），用宿主 chrome 底色兜住它 —— 代价是**画面缺顶部一格**（2026-10-11 用户报："开机时画面没有覆盖标题栏"）。

**现解**：**把原生覆盖层临时改透明**，画面铺满整窗（`coverTitlebar`，默认开）。
关键在于**不需要碰 DSH 本体一个字节** —— 宿主 preload 里的 `syncWindowsAppearance()` 本来就在盯着两个 CSS 变量（它用一个隐藏探针读计算样式，变化时经 `dsh-desktop:windows-appearance` IPC 落到 `mainWindow.setTitleBarOverlay({color,symbolColor})`）：

| 变量 | 作用 |
|---|---|
| `--dsw-specific-sidebar-fill` | 覆盖层**底色** → 写成 `rgba(0,0,0,0)` 即透明 |
| `--dsw-alias-label-primary` | 图标**颜色** → `titlebarControls` 决定何时写成不透明白 |

三条实测要点：

1. **必须写在 `body` 上，不能写 `html`**：DSH 的 token 是 `body{--dsw-specific-sidebar-fill:…}` 这种**直接在 body 上定义**的规则，写在 `html` 上的内联值会被它压掉。
2. **只在开机期间写、退出时逐条 `removeProperty` 还原**：标题栏在淡出那一刻就回到界面该有的样子。
3. **拖拽自己接回来**：覆盖层透明后，那一条改由面板的 `.boot-splash-top` 承担（`-webkit-app-region:drag`）。⚠ Electron 文档写明**拖拽区会吞掉所有指针事件** ⇒ 在标题栏那一条上点击不会触发"开声音/进入"，这是刻意的（它本来就是标题栏，用户在那里是要拖窗口）。

**你要求的"磨砂 + 关闭键鲜红"**：悬停时的磨砂底与关闭键红色是 **Electron/Windows 自己画的**，插件改不了、也不去改；插件只能控制**图标颜色**。所以 `titlebarControls: "hover"`（默认）的做法是：平时图标全透明，指针移进标题栏那一条才把图标写成白色 —— 这时系统自己的磨砂/红色就自然显现。

**兜底**：宿主若哪天不再重测配色，最坏只是恢复成"让出标题栏"的旧样子，不会更糟（那时把 `coverTitlebar` 关掉即可）。

## 全屏：为什么只能"点一下"

**结论：做不到"开机自动全屏"，只能"点一下进全屏"。** 这不是实现偷懒，是**内核级限制**：

1. **Chromium 要求全屏必须由用户手势触发**。`requestFullscreen()` 需要 transient activation，在 onload 里自动调用会被直接拒（[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) 写明 "Transient user activation is required"；[Electron #41090](https://github.com/electron/electron/issues/41090) 也明确 "it cannot fullscreen an app without a user interaction, like onload"）。
2. **DSH 没有向插件暴露窗口全屏接口**。桌面端主进程的全部 28 个 `dsh-desktop:` IPC 通道里没有任何一个与窗口全屏有关；preload 暴露给页面的 `dshDesktop` 只有 `browser` / `deviceInfo` / `keyboard` / `shortcuts` / `updates` 五项。主进程里唯一的 `setFullScreen` 调用是 macOS 关窗时的清理逻辑。
3. **插件拿不到 `BrowserWindow`**。`host.js` 跑在 Electron 用 `ELECTRON_RUN_AS_NODE=1` 拉起的普通 Node 子进程里，与主进程之间只有一条只认 `shutdown` / `quit-inspection` / `update-tasks` / `platform-session` 四种消息的通道。

所以本插件走**唯一可行的那条路**：`clickFullscreen`（默认开）—— 开机画面期间点一下就在**那一拍的用户手势里**发起 `requestFullscreen()`，整窗进真全屏。

**三条必须说清的行为**（前两条是 2026-10-11 用户实测报的 bug，已修 + 已加回归测试）：

- **单击只负责全屏，不再顺带进入界面**。原来的分支是「就绪了就 `enter()`」，而 `sound: "auto"` 下视频本来就不静音 ⇒ 这一下同时干了"进全屏"和"进入界面"两件事，画面刚全屏就被掐掉（用户原话："点击，进入全屏后视频就结束了，推测与之前点击跳过冲突了"）。**想提前进界面请双击**。
- **进入界面时退出全屏**（`exitFullscreenOnEnter`，默认开）。Windows 的真全屏会**收走窗口按钮**（最小化/最大化/关闭）——那是系统行为、插件改不了。若不退出，进界面后就没有任何窗口按钮可用、也点不到关闭键（用户原话："点击进入全屏后右上角的放大缩小退出图标消失了，不能缩小或退出"）。所以默认在 `enter()` 里 `exitFullscreen()`，把窗口还给用户。
  > 注：`titlebarControls: "hover"` 会把图标色设成全透明，而 `watchTitlebar` 只盯头 3 秒；退出全屏时面板会**重新评估一次**图标色，否则那个透明值会一直留着、按钮看着像"消失了"。
- **被拒会说原因、且只请求一次**：失败落到左下角提示行（`全屏被拒（NotAllowedError）`），不静默；后续点击不反复打扰浏览器。

### 想"跳过后保持全屏"：两条出路

把 `exitFullscreenOnEnter` **关掉**，双击跳过之后就保持全屏。此时系统窗口按钮**必然不存在**（真全屏的定义就是没有标题栏，Windows 不会把它画出来；插件也补不回来 —— 桌面端全部 28 个 `dsh-desktop:` IPC 通道里没有任何"最小化/最大化窗口"的入口），所以退出全屏只有两条路：

1. **键盘 Esc**（或 F11）—— 始终可用，不依赖任何开关。
2. **自绘「退出全屏」按钮**（`fullscreenExitButton`，默认开）—— 全屏期间常驻右下角，点一下退出、原生按钮全回来。这是**鼠标唯一的出路**。

按钮的两个实现要点（都是踩过的坑）：

- **它挂在覆盖层外面**。双击跳过后覆盖层会被整个移除，而全屏是要保持的 —— 按钮若在覆盖层里就会跟着消失，用户又"没有东西可点"了。所以它和覆盖层同级、独立存在；全屏结束时才把自己从 DOM 摘掉。
- **`isOwnUi` 必须认它**。全局手势监听在 window 的 **capture** 阶段，会**先于**按钮的 click 收到点击 ⇒ 不排除的话，点"退出全屏"会先被当成一次"点击画面"（又去请求全屏），按钮再退出，来回打架。

**双击跳过动画**（`doubleClickSkip`，默认开）：两次点击间隔 <320ms 直接进入界面。它与单击的区别在于**不受"外壳是否就绪"闸门限制** —— 开机头几秒单击只会先开声音并提示"就绪后自动进入"，而双击立刻放行。判据只对**指针**生效（键盘不计），否则用户连按两下 Esc 想退出全屏就会被误判成"跳过动画"。
